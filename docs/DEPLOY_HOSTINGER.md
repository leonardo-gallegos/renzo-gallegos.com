## Hosting-layer configuration

Confirm the plan supports these Apache-compatible `.htaccess` directives. Back up and merge with existing rules; this example is documentation, not an automatically deployed configuration. [Hostinger .htaccess guidance](https://www.hostinger.com/support/1583307-how-to-create-an-htaccess-file-at-hostinger/).

```apache
DirectoryIndex index.html
Options -Indexes
RewriteEngine On
RewriteCond %{HTTPS} !=on [OR]
RewriteCond %{HTTP_HOST} !^renzogallegos\.com$ [NC]
RewriteRule ^ https://renzogallegos.com%{REQUEST_URI} [R=301,L,NE]
ErrorDocument 404 /404.html
AddType application/xml .xml
AddType application/manifest+json .webmanifest
AddType image/png .png
AddType application/pdf .pdf
<IfModule mod_headers.c>
  Header always set X-Content-Type-Options "nosniff"
  Header always set Referrer-Policy "strict-origin-when-cross-origin"
  Header always set Permissions-Policy "camera=(), microphone=(), geolocation=()"
  Header always set X-Frame-Options "DENY"
</IfModule>
```

Test HTTP apex, HTTP www and HTTPS www: each must permanently reach `https://renzogallegos.com` with the same article path and query string, without loops. The rule uses a fixed hostname and preserves the query by default. If a proxy/CDN terminates TLS, `%{HTTPS}` may differ from public HTTPS: use the provider's HTTPS settings or documented trusted-proxy handling rather than blindly trusting a client-supplied forwarded header. Avoid competing rules. [Enable HTTPS](https://www.hostinger.com/support/1583201-how-to-enable-or-disable-https-for-your-website-at-hostinger/) only with a valid certificate.

`ErrorDocument 404 /404.html` serves the local exported page while retaining **HTTP 404**. Never rewrite unknown paths to Home, install an SPA fallback, or use an external error-document URL. Check a nonexistent article returns 404 and noindex; local QA cannot prove live Hostinger behavior.

Verify CSS (`text/css`), JS (JavaScript MIME), WOFF2 (`font/woff2`), PNG (`image/png`), manifest (`application/manifest+json`) and XML (`application/xml`, or `application/rss+xml` for feeds). Apply a feed-specific RSS type if supported. Correct MIME types are essential with nosniff. Cache hashed `_next/static/` assets long term; HTML/feeds/SEO files and the stable social image should revalidate or have short TTLs.

## Security policy draft

Next exports inline bootstrap/data scripts and the theme initializer. Optional GA4 adds inline configuration; Giscus injects a remote script/iframe. Do not enforce a CSP that breaks them. Begin with this **report-only compatibility draft**, inspect all routes/themes, derive hashes from the final exported inline scripts for a stricter policy, and retest each build. Configure a reporting endpoint only when a real one exists.

```text
Content-Security-Policy-Report-Only: default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'none'; form-action 'self'; script-src 'self' 'unsafe-inline' https://www.googletagmanager.com https://giscus.app; style-src 'self' 'unsafe-inline'; img-src 'self' data: https://*.google-analytics.com https://*.googletagmanager.com; font-src 'self'; connect-src 'self' https://*.google-analytics.com https://*.analytics.google.com https://*.googletagmanager.com; frame-src https://giscus.app; upgrade-insecure-requests
```

The inline allowance is a starting point, not a finalized strict policy. Remove optional origins when disabled; verify GA regional endpoints and Giscus when enabled. X-Frame-Options protects this site from embedding without preventing its Giscus iframe. Add HSTS only after HTTPS and affected subdomains are proven ready; do not casually add includeSubDomains/preload.
